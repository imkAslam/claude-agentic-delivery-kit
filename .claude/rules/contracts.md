# Contract rules

- Contracts (API specs, schemas, typed router definitions) are the agreement between roles. The **api-designer** writes them in Lane 2 (with the solution-architect's style decisions), and they are **frozen when G2 is approved**. The locations come from `.claude/project.json → contracts.paths`.
- After G2, nobody edits a contract directly. `guard-boundary.sh` blocks it. If one needs to change, stop and report `CONTRACT_CHANGE_NEEDED: <operation> — <exact change> — <reason>`. The orchestrator then opens a change request on G2 and a triage ticket for the api-designer.
- Consumers (frontend, mobile, QA) use clients or mocks generated by `contracts.codegen_cmd`. They never hand-write request or response types.
- Within a milestone, contract changes must be backward compatible, or must list every consumer ticket they break.
- Every operation defines: auth requirement, request schema, success response, error model (codes + shape), pagination/filtering where it applies, and idempotency for retried writes.
