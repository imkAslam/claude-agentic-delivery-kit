# Components: navigation and overlays

Build each from the project's UI library component and theme it with tokens. Reference systems: Radix and React Aria (overlay behavior), Material 3 and Apple HIG (navigation), the WAI-ARIA Authoring Practices for every keyboard pattern (`UI_RESOURCES.md`).

| Component | Use it for | Anatomy and sizes | States and behavior | Accessibility | Don't |
|---|---|---|---|---|---|
| **App shell (sidebar layout)** | The frame of a signed-in product | Sidebar 240–280 px (collapsed 56–72), top bar 56–64 px, content max width ~1200–1440 px with 24–32 px padding; the sidebar uses the **secondary** color role, content the dominant | expanded, collapsed (icons + tooltips), mobile (a drawer opened from the top bar), the choice remembered | Landmarks: `nav`, `header`, `main`; a skip link to main content | A sidebar and a full top menu both carrying primary navigation |
| **Sidebar navigation** | 5–9 top-level destinations | Item: icon 20 px + label; 36–40 px high; grouped with small headings; the current item clearly marked (background + weight); badges for counts | default, hover, focus, current, expanded section, collapsed | `aria-current="page"`; groups are lists; collapsed icons keep names | More than two levels; icons without labels in the expanded state |
| **Top bar** | Global context and tools | Left: product or page title, breadcrumbs; right: search, notifications, help, user menu; one row | default, scrolled (subtle border or shadow), mobile (menu button) | `header` landmark; icon buttons named | Stuffing page actions into the global bar |
| **Tabs** | Switching views of the same subject | 40–48 px high; the active tab marked by an indicator and weight; scrollable on overflow; 2–7 tabs | default, hover, focus, active, disabled; content loads per tab | APG tabs: arrows move between tabs, Tab enters the panel; `role="tablist"` | Tabs for steps in a process (use a stepper); tabs that navigate to unrelated pages |
| **Breadcrumbs** | Showing where a deep page sits | Links separated by a chevron; the current page is text; collapse the middle on small screens | default, hover, truncated | `nav` with a label; `aria-current="page"` on the last | Breadcrumbs on a flat app; the full history instead of the hierarchy |
| **Menu / dropdown** | A short list of actions or choices on demand | Opens from a button; 8 px from the trigger; items 32–36 px; icons optional but consistent; destructive items last, separated and colored | closed, open, item hover and focus, disabled item, submenu, checkmark items | APG menu button: Enter or Space opens, arrows move, Esc closes and returns focus | Menus more than two levels deep; hiding the main action in a menu |
| **Dialog (modal)** | A short task or decision that must interrupt | Width 400–560 px (larger only for complex content); a title, body, actions bottom-right (primary last) or stacked on mobile; a scrim behind | opening and closing (120–200 ms), submitting, error inside; closes on Esc and on scrim click unless data would be lost | Focus moves in and is trapped, returns to the trigger on close; `role="dialog"` with a label; background inert | A dialog on top of a dialog; a dialog for content that deserves a page; no way to close |
| **Confirmation dialog** | Destructive or irreversible actions | The title names the action and the object ("Delete project Atlas?"); the body states the consequence; the confirm button repeats the verb in the danger style; cancel is the safe default | default, confirming, failed | As dialog; initial focus on the safe action | "Are you sure?" with OK / Cancel; confirming harmless actions (offer undo instead) |
| **Drawer / sheet** | Detail or a form beside the page, keeping context | From the right 400–640 px on desktop; a bottom sheet on mobile; a header with a title and close; sticky footer actions | open, closed, loading content, unsaved changes warning | As dialog (modal), or a complementary region when non-modal | A drawer for a two-field edit (inline or a small dialog); nested drawers |
| **Popover** | Small, related, non-blocking content | Anchored to its trigger; an arrow optional; max width ~320 px; closes on outside click and Esc | closed, open, repositioned at screen edges | The trigger has `aria-expanded`; focus moves in only when it has controls | Essential information only in a popover; hover-only popovers with controls |
| **Tooltip** | A short label for an icon or truncated text | One line, max ~240 px; appears after ~500 ms on hover and immediately on focus; never interactive | hidden, visible | Linked with `aria-describedby`; available on keyboard focus; not the only place for essential help | Tooltips on touch as the only explanation; paragraphs in tooltips |
| **Stepper / wizard** | A process of 3–7 ordered steps | Step indicator with labels; one step per screen; Back and Next, with the final action named ("Create account"); progress saved | upcoming, current, done, error in a step, optional step | The current step announced; headings per step; Back never loses data | A wizard for one short form; hiding how many steps remain |
| **Command palette** | Fast keyboard access in tools with many actions | A centered dialog with a search field and grouped results; opened by a shortcut shown in the UI | empty, results, no results, loading, recent items | Combobox pattern; Esc closes | The only way to reach a feature |

## Navigation rules
- A user always knows where they are (current item marked, a page title that matches the link they clicked) and how to go back.
- The same destination has the same name everywhere.
- Mobile: primary navigation in a bottom bar (3–5 items) or a drawer; the back gesture always works.
- Overlays are the exception, not the default: prefer inline editing or a page when the task is long.
