# Components: data display

Build each from the project's UI library component and theme it with tokens. Reference systems: Carbon and Fluent 2 (dense data), Polaris (admin), Material 3 (`UI_RESOURCES.md`). Data loading and state: create-component → DATA_AND_STATE.md; performance: coding-foundations → PERFORMANCE.md.

| Component | Use it for | Anatomy and sizes | States and behavior | Accessibility | Don't |
|---|---|---|---|---|---|
| **Data table** | Comparing many records across the same fields | Header row (sticky), rows 40–52 px (compact 32–36), 12–16 px cell padding; text left, numbers right in tabular figures; row actions at the end; a toolbar above (search, filters, bulk actions, column settings); pagination or infinite scroll below | loading (skeleton rows, the header stays), empty (reason + action), error (retry), sorted column marked, row hover and selected, bulk selection bar, long text truncated with a tooltip | A real `<table>` with `<th scope>`; sortable headers are buttons with `aria-sort`; row selection by checkbox with a name | A table for 2–3 fields (use a list); horizontal scrolling on desktop without frozen key columns; centered columns |
| **List** | Scanning records with one main line and a little detail | Row: leading visual (avatar or icon), primary line, secondary line, trailing meta or action; 56–72 px rows; dividers or spacing, not both | loading, empty, error, hover, selected, unread, swipe or overflow actions on mobile | A list with list items; the whole row is one link or button when it navigates | Three actions per row always visible; mixed row heights without reason |
| **Card** | A self-contained summary that leads somewhere | Padding 16–24 px, even on all sides; one heading, supporting content, at most two actions; radius and border **or** shadow from tokens | default, hover (when clickable), focus, loading (skeleton), selected | A clickable card has one main link; nested interactive elements stay reachable | Cards inside cards; everything in a card; shadows and borders together |
| **Stat / metric** | One number that matters | Label (small), value (large, tabular), change vs. a period (arrow + sign + color **and** text), optional sparkline | loading (skeleton the value), no data ("—" with a reason), error | The change is text, not only an arrow or color | A wall of 12 equal stats; unlabeled numbers; precision nobody needs |
| **Badge / tag / status** | A short status or category | 20–24 px high, 6–8 px padding, 12 px text; a fixed, documented color per status; optional dot or icon | Static; a tag may be removable (× with a name) | Status is text, never color alone; enough contrast on its background; an error badge is a solid `danger.default` fill with `danger.on` text, or a red icon and edge with `text.default` text, never red text on a red tint | More than ~6 status colors; badges as buttons; ALL CAPS shouting |
| **Avatar** | A person or an entity | 24, 32, 40, 64 px; image with an initials fallback on a neutral or generated color; a group overlaps with "+N" | loaded, fallback, presence dot (with a text equivalent) | `alt` is the name, or empty when the name is next to it | Random bright colors that clash with status colors |
| **Chart** | A trend or a comparison (line: over time; bar: across categories; avoid pie beyond 3–4 parts) | A title that states the point; labeled axes with units; a legend only for 2+ series; the brand's chart palette (6–8 colors, color-blind safe); a tooltip with exact values | loading, empty ("no data for this period" + change range), error, hover or focus on a point | A text summary or a data table alternative; never color alone (use labels or patterns) | 3D, dual axes without need, more than ~6 series, truncated axes that mislead |
| **Description list (detail view)** | The fields of one record | Label and value pairs in one or two columns; labels muted, values prominent; grouped under headings; an Edit action per group | loading, missing value shown as "—", long values wrap | `<dl>` with `<dt>` and `<dd>` | Editable-looking fields that are read-only; an empty value with no marker |
| **Timeline / activity feed** | What happened, in order | Time marker, actor, action in a sentence, optional detail; grouped by day; newest first | loading more, empty, new items indicator, unread marker | A list in chronological order; times in `<time>` with a full date available | Relative times only ("3d") with no exact date |
| **Pagination** | Moving through pages of results | Previous / next always; page numbers when the total is known; a page-size choice for tables; "Showing 21–40 of 312" | first page (previous disabled), last page, loading the next page, cursor mode (next / previous only) | A `nav` with a label; the current page marked with `aria-current` | Infinite scroll on tables people need to reach the end of or return to a place in |
| **Empty state** | A place with no content yet, or no results | A short title that says what belongs here, one sentence of help, one primary action; an optional simple illustration or icon | first use (invite to create), no results (suggest clearing filters), no permission, error | The action is a real button; decorative art is hidden from assistive technology | A blank area; "No data"; blaming the user |
| **Skeleton** | Loading content whose shape is known | Blocks matching the final layout's sizes and positions; a subtle shimmer; shown after ~200 ms, for at least ~300 ms | loading → content with no layout shift | `aria-busy` on the region; reduced motion stops the shimmer | Spinners for whole pages; skeletons that don't match the result |

## Numbers, dates and text
- Format by locale: thousands separators, currency with its code or symbol, dates as "12 Mar 2026", times with a zone when it matters.
- Truncate with an ellipsis only when the full value is available (tooltip or detail view). Never truncate numbers.
- Right-align numbers in tables; use tabular figures so digits line up.
