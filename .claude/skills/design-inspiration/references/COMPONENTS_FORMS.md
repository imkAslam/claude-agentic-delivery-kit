# Components: inputs and forms

Build each from the project's UI library component and theme it with tokens. Sizes are defaults; the tokens and `DESIGN.md › Components` win. Reference systems: GOV.UK (forms and errors), Carbon, Material 3, React Aria (`UI_RESOURCES.md`). Form logic and validation: coding-foundations → FORMS_AND_VALIDATION.md.

| Component | Use it for | Anatomy and sizes | States and behavior | Accessibility | Don't |
|---|---|---|---|---|---|
| **Button** | Actions. One primary per view; secondary, ghost, danger and link variants | Heights sm 32, md 40, lg 48 px; horizontal padding = 1.5–2× the vertical; icon 16–20 px with an 8 px gap; label in sentence case, verb + object ("Save changes") | default, hover, focus-visible, active, disabled, loading (spinner replaces or precedes the label, width does not jump, double submit blocked) | Native `<button>`; icon-only needs an accessible name; disabled has a reason nearby | Two primaries side by side; a button that navigates (use a link); vague labels ("OK", "Submit") |
| **Text input** | Short free text | Label above (never placeholder-only); height 40 px; 12 px horizontal padding; helper text below; optional leading icon or trailing action | default, focus (ring token), filled, disabled, read-only, error (red border + message + icon), success only when it helps | `<label for>`; error linked with `aria-describedby`; correct `type`, `autocomplete` and `inputmode` | Placeholder as the label; validating on every keystroke before the user finishes |
| **Textarea** | Long text | Min 3 rows; grows to a max, then scrolls; a counter when there is a limit | Same as text input; the counter warns near the limit | As text input | Fixed tiny boxes; a silent hard limit |
| **Select / combobox** | One of many. Native select up to ~7 simple options on mobile; a searchable combobox beyond ~10 | Trigger looks like an input with a chevron; list max height ~320 px; selected item marked | open, closed, option hover and active, selected, disabled option, empty search result, loading options | APG listbox / combobox pattern: arrows move, Enter selects, Esc closes, type-ahead | A select for 2–3 options (use radios); long unsearchable lists |
| **Checkbox and radio** | Checkbox: independent choices. Radio: exactly one of 2–6 | Control 16–20 px; the label is clickable; 8 px gap; a group has a legend | unchecked, checked, indeterminate (checkbox), focus, disabled, error on the group | `fieldset` + `legend`; the whole row at least 24 px high (44 on touch) | Radios without a default when one is required; a checkbox for an instant action (use a switch) |
| **Switch** | A setting that applies immediately | Track ~36×20 px; label left or right, state implied by the label, not by "on/off" text alone | off, on, focus, disabled, saving | `role="switch"` with `aria-checked` | A switch inside a form that needs "Save" (use a checkbox) |
| **Date and time picker** | Dates the user must choose from a calendar; a plain field for known dates (birth date) | Input with a calendar button; popover calendar; week starts per locale; clear min and max | open, selected, range, today marked, disabled dates, invalid typed date | Typed entry always possible; APG date-picker grid keys; the format shown in the helper text | Forcing calendar clicking for a birth year; ambiguous formats (03/04/05) |
| **File upload** | Attaching files | Drop zone with a button fallback; accepted types and max size stated; a row per file: name, size, progress, remove | idle, drag-over, uploading (progress), done, failed (reason + retry), too large or wrong type | A real file input behind the button; progress announced; remove buttons named with the file | A silent failure; hiding the limits until after an error |
| **Search field** | Finding items in a list or the whole app | Leading search icon; clear button when filled; results debounce 250–300 ms; optional shortcut hint | empty, typing, loading, results, no results (with a suggestion), error | `role="search"`; results announced; Esc clears | Searching on every keystroke without debounce; an empty area when nothing matches |
| **Code / OTP input** | One-time codes | One field (preferred) or segmented boxes; numeric keyboard; auto-submit on the last digit; resend with a countdown | empty, filled, error (clear and refocus), expired, resend cooling down | `autocomplete="one-time-code"`; paste works; a single labelled field for assistive technology | Blocking paste; clearing everything on one wrong digit without a message |
| **Form layout** | Any group of fields | One column by default; labels above; related fields grouped under a heading with 24–32 px between groups, 16 px between fields; required or optional marked consistently; primary action bottom-left (or full width on mobile), secondary next to it | pristine, dirty, submitting (button loading, fields locked), submitted, server error mapped to fields, form-level error summary at the top for long forms | The error summary links to fields and takes focus on submit failure; a logical tab order | Multi-column forms that break reading order; resetting the form on error; disabled submit with no hint why |

## Validation and messages
- Validate on blur and on submit; re-validate on change only after a field has shown an error.
- A message says what is wrong **and how to fix it** ("Enter a date after 1 January 2020"), next to the field, with an icon and not by color alone.
- Keep what the user typed. Never clear a field because it was invalid.
